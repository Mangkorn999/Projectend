# Frontend 13 — หน้า "คู่มือการใช้งาน" + ภาพสาธิตเคลื่อนไหว

ไฟล์ (`frontend/src/design/`): `userManual.jsx` (560), `userManualEn.jsx` (473), `manualParts.jsx` (24), `manualDemo.jsx` (211), `manualDemos.jsx` (306), `manualDemosMore.jsx` (651), `manualDemoEn.js` (476)
เมนู "คู่มือการใช้งาน" ของ **officer** (`page === 'manual'` ใน `app.jsx`) — **เนื้อหา static ล้วน ไม่เรียก backend ไม่ผ่าน `i18n.js`**

> **อธิบายแบบกลไก ไม่ไล่เนื้อหาทีละบรรทัด:** ไฟล์เหล่านี้ส่วนใหญ่เป็น "ข้อความคู่มือ" (JSX/HTML ของเนื้อหา) — ส่วนที่เป็น logic คือ ตัวสารบัญ, ตัวเล่นภาพสาธิต, ตัวแปลภาษา
> **กฎการดูแล:** แก้เนื้อหาฉบับไทย ต้องแก้ฉบับอังกฤษให้ตรงกัน; แก้ UI จริงของระบบ ต้องแก้สคริปต์สาธิตให้ตรง (คู่มือที่ไม่ตรงระบบจริงเสียหายกว่าไม่มีคู่มือ)

## 4. `manualDemo.jsx` — เครื่องเล่นภาพสาธิต `StepDemo`

**หลักการ: ไม่ใช้วิดีโอ/GIF** — วาด "หน้าจอจำลอง" ด้วย React + class จริงของระบบ (`btn`, `badge`, `card`) แล้วให้ "เมาส์จำลอง" เลื่อนไปคลิกปุ่มทีละขั้นตามสคริปต์. ข้อดี: คมทุกขนาดจอ ไฟล์เล็ก แก้ข้อความ/ขั้นตอนในโค้ดได้ ไม่ต้องอัดหน้าจอใหม่เมื่อ UI เปลี่ยน
**ลำดับต่อ 1 ขั้น:** `phase='move'` (เมาส์เลื่อนไปปุ่มเป้าหมายที่มี `data-demo="ชื่อ"` + วงแหวนเรือง) → `phase='click'` (ริ้วคลื่น → หน้าจอจำลองเปลี่ยน → พักให้อ่าน) → ขั้นถัดไป; ครบแล้วพักแล้ววนใหม่

| บรรทัด | อธิบาย |
|---|---|
| 19-20 | `STAGE_W = 640` (กว้างหน้าจอจำลอง; จอเล็กกว่าย่อทั้งก้อนด้วย `transform: scale`), `MOVE_MS = 1000` (ต้องตรงกับ CSS transition ของ `.mn-cursor`) |
| 22-23 | `prefersReducedMotion()` — `window.matchMedia('(prefers-reduced-motion: reduce)').matches` (เช็ค `typeof window` กัน SSR) |
| 25 | `StepDemo({ title, steps, stage, height })` — `steps[k] = {target, text, hold?}`; `stage(done)` = ฟังก์ชันที่คืนหน้าจอจำลองเมื่อคลิกไปแล้ว `done` ขั้น |
| 29-41 | state: `reduced` (**lazy init `useState(prefersReducedMotion)`** ส่งฟังก์ชันตรง ๆ), refs 4 ตัว (`wrapRef`, `stageRef`, `cursorRef`, `ringRef`), `scale`, `offset`, `i` (ขั้นปัจจุบัน), `phase`, `loop` (นับรอบ — ใช้เป็น `key` ให้หน้าจอจำลองเริ่มใหม่สะอาด), `visible`, `userPaused` |
| 43 | `playing = visible && !userPaused && !reduced` |
| 46 | **`done = phase === 'click' ? i + 1 : i`** — จำนวนขั้นที่ "คลิกไปแล้ว"; ตอนเมาส์ยังเคลื่อนอยู่ขั้นนี้ยังไม่ถูกคลิก จึงนับแค่ขั้นก่อนหน้า |
| 49-58 | `ResizeObserver` (ตรวจ `typeof ResizeObserver === 'undefined'` กันสภาพแวดล้อมที่ไม่มี) — ย่อหน้าจอจำลองให้พอดีความกว้างที่มี: `scale = min(1, กว้างจริง / 640)`; `offset` เว้นซ้ายให้อยู่กลาง |
| 61-67 | `IntersectionObserver` threshold 0.35 — **เล่นเฉพาะตอนเลื่อนมาเห็นบนจอ** ไม่เล่นทิ้งไว้ข้างล่างโดยไม่มีคนดู |
| 71-86 | **`useLayoutEffect`** — วัดตำแหน่งปุ่มเป้าหมาย (`querySelector('[data-demo="..."]')`, `getBoundingClientRect()` หารด้วย `scale` ชดเชยการย่อ) แล้ว **"สั่ง DOM ตรง ๆ"** ย้ายเมาส์/วงแหวน (`style.transform`, `Object.assign(style, {...})`) ไม่ใช้ state (ตำแหน่งเป็นเรื่องของ DOM ล้วน ให้ CSS transition ทำแอนิเมชันต่อเอง). ใช้ `useLayoutEffect` (ไม่ใช่ `useEffect`) เพราะรันก่อน browser วาดจอ ไม่เห็นเมาส์กระโดด |
| 89-104 | **ไทม์ไลน์** (เฉพาะตอน `playing`): `phase==='move'` → `setTimeout(() => setPhase('click'), MOVE_MS)`; `'click'` → `setTimeout(advance, hold ?? 1600 (+1400 ขั้นสุดท้าย))`; `advance`: ยังมีขั้นถัดไป → `setI(i+1)` ไม่งั้น `setLoop(l => l+1); setI(0)` (วนใหม่) แล้ว `setPhase('move')`; cleanup `clearTimeout` |
| 106-112 | `goto(k)`, `replay`, `next` (ขั้นนี้ยังไม่คลิก → คลิกให้ก่อน) — ผู้ตั้งค่า "ลดการเคลื่อนไหว" ไม่เล่นเอง ใช้ปุ่ม "ขั้นถัดไป" ทีละขั้น |
| 114-157 | JSX: `<figure>`; ป้าย+ชื่อ; หน้าจอจำลอง `aria-hidden="true"` (ขั้นตอนเดียวกันเขียนเป็นรายการตัวอักษรด้านล่างแล้ว) — `translateNode(stage(done), lang)` แปลข้อความไทยในหน้าจอจำลองเป็นอังกฤษเมื่อเลือก EN; `key={loop}` รีเซ็ตทั้งก้อนเมื่อวนรอบ; เมาส์ = SVG ลูกศร + ริ้วคลื่น (`key={`${loop}-${i}`}` ให้เล่นใหม่ทุกคลิก); แถบควบคุม (หยุด/เล่น, เริ่มใหม่, ขั้นถัดไป, `role="status"` ประกาศขั้นปัจจุบัน); รายการขั้นตอนตัวอักษร `<ol>` (`aria-current="step"`, ปุ่มกระโดดไปขั้นนั้น) |
| 163-210 | **ชิ้นส่วนหน้าจอจำลอง** ใช้ class จริงของระบบ: `MockFrame` (กรอบหน้าต่าง), `MockToast`, `MockTyped` (ข้อความพิมพ์ทีละตัว — เริ่มตอน mount), `MockModal`, `TONES` + `MockBadge`, `Field`, `Box` (มี `data-demo`), `Btn` (`tabIndex={-1}` ไม่ให้โฟกัสได้จริงในหน้าจอจำลอง) |

## 5. `manualDemos.jsx` + `manualDemosMore.jsx` — สคริปต์สาธิต
แต่ละเรื่อง = object `{ title, steps, stage, height? }` (ดูตัวอย่าง `approveDemo` บรรทัด 80-107):
- `steps` = `[{ target: 'row-review', text: 'คลิกปุ่ม "ตรวจสอบ" ...', hold?: 2000 }, ...]` — `target` ต้องมี `data-demo` ตรงกันบนหน้าจอจำลอง ณ ตอนทำขั้นนั้น

- `manualDemos.jsx`: `DetailScreen` (หน้ารายละเอียดจำลอง), `PendingActions`/`ConfirmedActions`, สคริปต์ `approve`, `reject`, `revoke`, `import`, `pending`, `round`; **`DEMOS = {..., ...MORE_DEMOS}`** รวมกับชุดใน `manualDemosMore.jsx` (spread merge); `Demo({name})` ค้นหาแล้วคืน `<StepDemo .../>`
- `manualDemosMore.jsx`: ชิ้นส่วนช่วย (`ImportTabs`, `StudentTable`, `UsersTable`, ฯลฯ) + สคริปต์ที่เหลือ (เพิ่มทีละคน, จับคู่คอลัมน์, แถวที่ข้าม, สิทธิ์, รีเซ็ตรหัส, แก้ไข/ลบนักศึกษา, ขยายรอบ, รายวิชา, ผู้ใช้, ข่าว, รายงาน, แดชบอร์ด, แผงส่งออก) → `export const MORE_DEMOS`

## 6. `manualDemoEn.js` — พจนานุกรมแปลภาพสาธิต
**ทำไมใช้พจนานุกรมแทนเขียนสคริปต์ซ้ำเป็นอังกฤษ:** สคริปต์สาธิตยาวกว่า 900 บรรทัด ถ้าเขียน 2 ภาษา แก้ UI ต้องไล่แก้ 2 ที่ — ที่นี่เก็บแค่ "ข้อความ" โครงหน้าจอจำลองมีชุดเดียว
| ส่วน | อธิบาย |
|---|---|
| `ManualLangContext` / `useManualLang` (17-18) | `createContext('TH')` + hook อ่านภาษา |
| `THAI = /[฀-๿]/` (20) | regex ช่วงอักษรไทย (U+0E00–U+0E7F) ใช้ตรวจว่าข้อความมีภาษาไทยไหม |
| `EN = {...}` (22-430) | object คำไทย → อังกฤษ (key เป็นข้อความไทยเต็ม) ใช้คำเดียวกับ `i18n.js` ฝั่ง EN ของระบบจริง |
| `tr(text, lang)` (432-443) | ตัวแปลข้อความเดียว: ไม่ใช่ EN / ไม่ใช่ string / ไม่มีไทย → ปล่อยผ่าน; `core = text.trim()`, หา `EN[core] ?? EN[text]`; **คงช่องว่างหน้า/หลังไว้** (`lead`/`tail`) เพราะข้อความที่ถูกผ่าซีกด้วยตัวแปร เช่น "ผ่าน {n} คน" มาเป็นชิ้น "ผ่าน " กับ " คน"; ไม่มีในตาราง = แสดงไทยตามเดิม (ไม่พัง แต่เห็นว่าตกหล่น) |
| `translateNode(node, lang)` (445-469) | **เดิน React element ทั้งต้นแล้วแปลทุกจุด** (recursion): string → `tr`; array → `.map(translateNode)`; ไม่ใช่ element → คืนเดิม; ถ้ามี prop `data-en="..."` ใช้ข้อความนั้นแทน (กรณีคำไทยเดียวกันแปลต่างตามบริบท เช่น "ถอนสิทธิ์" นักศึกษา vs บัญชีผู้ใช้); วน props แปลเฉพาะที่เป็น string ไทย หรือ element/array (เช่น `footer`) **ไม่แตะ function/object** (`style` ฯลฯ); สร้าง element ใหม่ด้วย `cloneElement(node, changed, ...children แปลแล้ว)` ส่งลูกเป็น argument แยกตัว (ไม่ใช่ array ใน props) ไม่ให้ React ฟ้อง key ซ้ำ |
| `PLAYER_TEXT` (471-476) | ข้อความของตัวเล่นเอง (ปุ่ม/ป้าย) แยก TH/EN — ไม่ผ่าน `translateNode` เพราะไม่ใช่เนื้อหาในหน้าจอจำลอง; `now`/`goto` เป็นฟังก์ชันรับตัวแปรคืนข้อความ |
> เพิ่มข้อความไทยใหม่ในสคริปต์สาธิตเมื่อไหร่ ให้มาเพิ่มคำแปลที่นี่ (สลับเป็น EN แล้วเปิดคู่มือ — เห็นไทยค้างในภาพสาธิต = ยังไม่มีคำแปล)
