# Frontend 14 — ระบบสองภาษา TH/EN (`i18n.js`, 2,318 บรรทัด)

ไฟล์เดียว — ส่วนใหญ่ (≈ 2,270 บรรทัด) เป็น **พจนานุกรมข้อความ** ที่เหลือเป็นฟังก์ชันสั้น ๆ 4 ตัว
ใช้ทุกหน้าหลัง login ผ่าน `const tt = (key, vars) => t(lang, key, vars)`; `lang` เก็บที่ `app.jsx` (`'TH'|'EN'`) และส่งลงเป็น prop

> ไม่อธิบายข้อความทีละบรรทัด (เป็นแค่คู่ key → ข้อความ) — อธิบายโครงสร้างและกฎการใช้

## โครงสร้าง `DICT` (6-2278)
```js
const DICT = {
  TH: { 'status.DRAFT': 'ยังไม่กรอก', 'notif.rejectedSub': 'รอบที่ {attempt}/{year} · {remark}', ... },   // บรรทัด 7-1148
  EN: { 'status.DRAFT': 'Not submitted', ... },                                                          // บรรทัด 1149-2278
};
```
- **key** = ชื่อแบบมีจุดแบ่งกลุ่ม `หน้า.หัวข้อ` เช่น `status.*`, `topbar.*`, `notif.*`, `role.*`, `nav.*`, `dashReal.*`, `examform.*`, `officer.students.*`, `importReal.*`, `usersMgmt.*`, `roundsMgmt.*`, `newsMgmt.*`, `reports.*`, `export.*`, `evidence.*`, `roundPhase.*`, `common.*`, `select.*`, `pagination.*`
- **ตัวแปรในข้อความ** เขียนด้วยปีกกา `{n}`, `{year}`, `{attempt}`, `{remark}` … แทนค่าตอนเรียก `tt('key', { n: 5 })`
- TH กับ EN มี **key ชุดเดียวกัน** — เพิ่ม key ใหม่ต้องเพิ่มทั้งสองภาษา (ไม่มีใน EN จะตกไปใช้ไทย; ไม่มีทั้งคู่จะแสดงชื่อ key ตรง ๆ ให้เห็นว่าตกหล่น)

## ฟังก์ชัน
### `t(lang, key, vars)` (2308-2313)
```js
export function t(lang, key, vars) {
  const s = (DICT[lang] && DICT[lang][key]) ?? DICT.TH[key] ?? key;
  if (!vars) return s;
  return Object.keys(vars).reduce((acc, k) => acc.replaceAll('{' + k + '}', vars[k]), s);
}
```
| ส่วน | อธิบาย |
|---|---|
| `DICT[lang] && DICT[lang][key]` | ข้อความของภาษาที่เลือก (ตรวจ `DICT[lang]` มีอยู่ก่อน) |
| `?? DICT.TH[key]` | **fallback ภาษาไทย** — ไม่มีคำแปล EN → ใช้ไทย (หน้าไม่พัง) |
| `?? key` | fallback สุดท้าย = ตัว key เอง (เห็นง่ายว่าลืมเพิ่ม) |
| `Object.keys(vars).reduce(...)` | วนทุกตัวแปรที่ส่งมา แทน `{ชื่อ}` ในข้อความทีละตัวด้วย `replaceAll` (`acc` = ข้อความสะสมหลังแทนแต่ละรอบ) |
> `??` (nullish coalescing) ต่างจาก `||` ตรงที่เฉพาะ `null`/`undefined` เท่านั้นที่ข้ามไปใช้ค่าถัดไป (สตริงว่าง `''` ถือเป็นข้อความที่ตั้งใจ)

### `subjectName(lang, code, fallbackName)` (2291-2294)
ชื่อวิชา 8 วิชาแปลอังกฤษโดยตาราง `SUBJECT_NAME_EN` (key = รหัสวิชา 1101-1108) — **backend เก็บแค่ภาษาไทย** (schema ไม่มี field EN) จึง map ฝั่ง frontend; รหัสไม่รู้จัก (วิชาที่เจ้าหน้าที่เพิ่มทีหลัง) คืนชื่อเดิมจาก DB

### `roomName(lang, name)` (2303-2306)
ชื่อห้องเรียนมาจาก DB ตรง ๆ — `ROOM_NAME_EN` map ชื่อไทยที่ seed ไว้ ("ห้องเรียนปกติ"/"ห้องเรียนอังกฤษ") ชื่ออื่นคืนเดิม

### `pick(lang, obj, field)` (2315-2318)
เลือก `${field}_en` ของ object ข้อมูลจำลอง (mock) เมื่อเป็น EN และมีค่า ไม่งั้นใช้ `field` — ตกค้างจากต้นแบบ ใช้กับ `student.jsx` เก่า (ข้อมูลจริงไม่ใช้)

## หลักการเขียนข้อความบนจอ (ทั้งโปรเจกต์)
- ภาษาไทยทางการ บอก "เกิดอะไรขึ้น + ทำอะไรต่อ" (ผู้ใช้เป็นพยาบาล ไม่ใช่โปรแกรมเมอร์)
- **ห้ามโชว์คำภาษาอังกฤษจาก DB/โค้ดตรง ๆ** เช่น `officer`, `exam_result`, `P2002` — แปลผ่านฟังก์ชัน/ตารางก่อนเสมอ (ดู `evidenceFiles.js`, ข้อความ error ใน `errorHandler.js`)
- ข้อความ error จาก backend เป็นไทยอยู่แล้ว — หน้าจอแสดง `e.message` ตรง ๆ (`ApiError`) ส่วน `fallbackMessage(status)` ใน `api.js` ใช้เมื่อ backend ไม่ส่งข้อความมา
- ภาษาของ **หน้า Login, บังคับเปลี่ยนรหัส, กรอกโปรไฟล์** ไม่ผ่าน `i18n.js` (ข้อความฝังในไฟล์เพราะอยู่ก่อน login/ก่อนมี `lang` จาก app.jsx) — Login มีสวิตช์ TH/EN ของตัวเอง
- คู่มือการใช้งานมีระบบแยกของตัวเอง ([frontend 13](13-คู่มือการใช้งาน-และ-ภาพสาธิต.md))
