## 0. สรุปสั้น

**สภาพตอนนี้: เสถียรพอใช้งานจริงและสาธิตได้** — เทส API อัตโนมัติมี 26 ไฟล์ (1,187 ข้อตรวจ นับจากการรันจริง 5 ต.ค.) + เทสหน้าเว็บ 1 ชุด (Chrome จริง) ครอบคลุม flow หลัก, สิทธิ์ 4 บทบาท, การแข่งกันเขียน, ไฟล์แนบ, ส่งออก และกฎ "นับเฉพาะใบที่ยืนยันแล้ว" ไว้แล้ว

**ตรวจโค้ดรอบนี้เจอ 18 ประเด็น** (รายละเอียดข้อ 1.2):

| ระดับ | จำนวน | ตัดสินใจ |
|---|---:|---|
| สูง (ตัวเลขสถิติอาจผิด) | 2 | B-01 ต้องถามมังกรก่อน · B-02 แนะนำแก้ก่อนสอบ |
| กลาง | 4 | แก้ 3 (เล็ก ไม่กี่บรรทัด) · ไม่แก้ 1 (ต้องแก้ schema — บันทึกเป็นข้อจำกัด) |
| ต่ำ | 12 | แก้ 1 (B-12) · แก้ถ้ามีเวลา/ถ้าเทสเจอจริง 4 (B-04, B-08, B-13, B-14) · ไม่แก้ 7 (อธิบายเหตุผลได้) |

**สิ่งที่ต้องทำต่อ (ตามลำดับ):** ตัดสินใจ B-01 → แก้ B-02, B-03, B-18 (backend) + B-06, B-12 (frontend) → รันเทสเดิมทั้งชุด → เขียนเทสใหม่ `phase33` (ข้อที่ติด 🆕) → เทสมือผ่านหน้าเว็บตามบทบาท (ข้อ 5–8) → เทสครบวงจร (ข้อ 10) → บันทึกผล

## 12. ตรวจข้อมูลนำเข้า / ค่าผิดรูปแบบ (ยิง API ตรง)

| ประเภทค่า | ตัวอย่าง |
|---|---|
| id ผิดรูป | `abc`, `-1`, `0`, `1.5`, `99999999999` (เกิน int), ว่าง |
| ชนิดผิด | ตัวเลขแทนข้อความ, object/array แทนข้อความ, `"true"` แทน boolean, `null` |

| เส้นทางไม่มีจริง | `GET /api/xxx` → 404 JSON ไทย (ไม่ใช่หน้า HTML) |
