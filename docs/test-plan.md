# แผนทดสอบและแก้บั๊ก — ตาม flow การใช้งานจริงของคณะ

ร่าง 1 ต.ค. 2569 · ใช้ประกอบบทที่ 5 (การทดสอบ) ได้

---

## 1. Flow จริงที่ใช้เป็นหลักในการทดสอบ

```
[เจ้าหน้าที่] นำเข้ารายชื่อนักศึกษาชั้นปีสุดท้าย (1 รุ่น = 1 ปีการศึกษา)
     ↓
[เจ้าหน้าที่] สร้างรอบที่ 1 (เลือกวิชา + วันเปิด-ปิด) → โพสต์ประกาศผูกกับรอบ
     ↓
[นักศึกษา] ได้ใบคะแนน → กรอก ผ่าน/ไม่ผ่าน รายวิชา + แนบไฟล์ใบคะแนน (PDF หรือรูปภาพ, หลายไฟล์) → ส่ง
     ↓
[เจ้าหน้าที่ + ผู้ช่วยตรวจ] ตรวจเทียบไฟล์ → ยืนยัน / ตีกลับพร้อมเหตุผล (ตรวจได้ทั้งระหว่างรอบและหลังปิดรอบ)
     ↓
รอบ 1 ปิด → สรุป "ผ่านครั้งแรก"
     ↓
[เจ้าหน้าที่] สร้างรอบที่ 2 → ประกาศถึง "เฉพาะผู้ที่ยังไม่ผ่านครบ" → นักศึกษากลุ่มนั้นกรอกเฉพาะวิชาที่เหลือ → ตรวจ
     ↓
รอบที่ 3 เหมือนรอบที่ 2 → จบปี: สรุป "ผ่านภายในปีแรก" / "ไม่ผ่านภายในปีแรก"
(หลังจากนั้นนักศึกษาที่ยังไม่ผ่านไปสอบเอง ระบบไม่ติดตามต่อ)
```

**ผลลัพธ์ที่คณะต้องได้จริง:** รายชื่อผ่านครั้งแรก · รายชื่อไม่ผ่านภายในปีแรก · ข้อมูลนักศึกษา (ชื่อ-นามสกุลไทย/อังกฤษ เบอร์ ห้อง ฯลฯ)
**ผู้ใช้หลัก:** เจ้าหน้าที่และนักศึกษาพยาบาล (ไม่ใช่คนไอที) → ข้อความต้องเป็นทางการ อ่านเข้าใจทันที ไม่มีศัพท์เทคนิค

## 2. ช่องว่างระหว่าง flow ที่ต้องการ กับระบบตอนนี้

| # | ต้องการ | ระบบตอนนี้ | ต้องทำ |
|---|---|---|---|
| G1 | แนบใบคะแนนได้หลายไฟล์ ทั้ง PDF และรูปภาพ | แนบได้ **1 ไฟล์ PDF เท่านั้น** (อัปโหลดใหม่ = แทนที่ไฟล์เดิม) | เพิ่มฟีเจอร์ — ตาราง `certificates` รองรับหลายไฟล์อยู่แล้ว **ไม่ต้องแก้ schema** |
| G2 | ประกาศรอบ 2–3 ถึงเฉพาะผู้ที่ยังไม่ผ่านครบ | ทุกคนในรุ่นเห็นประกาศทุกรอบของรุ่น | **ต้องตัดสินใจ** (ดูข้อ 5) |
| G3 | รายชื่อ "ไม่ผ่านภายในปีแรก" | มีตัวเลขบนแดชบอร์ด แต่ **ส่งออกรายชื่อได้แค่ "ผ่าน/ไม่ผ่านครั้งแรก"** | เพิ่มไฟล์ส่งออก "ผ่าน/ไม่ผ่านภายในปีแรก" |
| G4 | ตรวจหลังปิดรอบ แล้วตีกลับได้ | ตีกลับได้ แต่ **นักศึกษาแก้ไม่ได้เพราะรอบปิดแล้ว** ต้องเลื่อนวันปิดรอบทั้งรอบ (และทำไม่ได้ถ้ารอบถัดไปเปิดอยู่) | **ต้องตัดสินใจ** (ดูข้อ 5) |
| G5 | เจ้าหน้าที่เพิ่ม "ผู้ช่วยตรวจ" ได้ | **มีแล้ว** (บทบาท `reviewer` ตรวจ/ยืนยัน/ตีกลับได้ เปิดไฟล์ได้ จัดการอื่นไม่ได้) แต่ชื่อเรียกบนจอคือ "เจ้าหน้าที่ตรวจสอบ" และเมนูชื่อ "ผู้ใช้งานผู้บริหาร" ทำให้หาไม่เจอ | เปลี่ยนชื่อเป็น "ผู้ช่วยตรวจสอบ" / เมนู "จัดการผู้ใช้งาน" |
| G6 | ข้อความทางการ เข้าใจง่าย | ยังมีข้อความเทคนิคหลุดถึงผู้ใช้บางจุด เช่น `Request failed (500)`, `certificate_type ต้องเป็น ...` | ตรวจทุกหน้า + ข้อความ error |
| G7 | โค้ดอ่านง่ายสำหรับผู้เริ่มต้น | โค้ดส่วนใหญ่ใช้ `.map/.filter/Map/Set` | โค้ดที่เขียนใหม่/แก้ในรอบนี้ใช้ `if/else` + `for` เป็นหลัก พร้อมคอมเมนต์ไทย |

### บั๊กที่สงสัย (ต้องพิสูจน์ด้วยเทสก่อนแก้)
**B1 — "ผ่านภายในปีแรก" นับวิชาที่ยกมาจากใบที่ถูกตีกลับภายหลัง**
ลำดับเหตุการณ์: รอบ 1 ใบยังรอตรวจ (วิชา A ผ่าน) → เปิดรอบ 2 → นักศึกษาส่งรอบ 2 (วิชา A ถูกยกมาเป็นผ่านอัตโนมัติ) → เจ้าหน้าที่ **ตีกลับใบรอบ 1** → ยืนยันใบรอบ 2
ผล: ระบบนับว่าผ่านวิชา A ทั้งที่หลักฐานวิชา A ถูกตีกลับ → ตัวเลข "ผ่านภายในปีแรก" สูงเกินจริง
สาเหตุในโค้ด: `dashboard.service.js → buildYearSummary` นับ `is_passed` ของใบที่ยืนยันแล้ว **รวมวิชาที่ `carried_forward`**
โอกาสเกิด: กลาง (เจ้าหน้าที่ 1 คน นักศึกษา 200 คน ตรวจไม่ทันก่อนเปิดรอบถัดไปได้) · ผลกระทบ: สูง (ตัวเลขที่ส่งสภา)
แนวแก้: ตัวเลขระดับปีนับเฉพาะวิชาที่ "สอบจริงและผ่าน" (ไม่นับ carried) — ใบต้นทางที่ยืนยันแล้วจะนับวิชานั้นให้อยู่แล้ว

## 4. ลำดับการทำงาน (หลังได้ข้อตัดสินใจ)

1. **เขียนเทสอัตโนมัติรอบใหม่** `smoke-phase25-real-flow.mjs` ตามกรณี ➕ ทั้งหมด (รันบนฐานข้อมูลชั่วคราว ไม่แตะข้อมูลจริง)

3. **ทำฟีเจอร์ G1 (หลายไฟล์ + รูปภาพ)**, **G3 (ส่งออกผ่าน/ไม่ผ่านภายในปีแรก)**, **G5 (ชื่อผู้ช่วยตรวจ)**, และ G2/G4 ตามที่ตัดสินใจ
