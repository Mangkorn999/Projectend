# 08 — แผนที่จุดแก้โค้ด ("ถ้ากรรมการสั่ง … ต้องเปิดไฟล์ไหน แก้อะไร พิสูจน์อย่างไร")

ไฟล์นี้สำคัญที่สุดสำหรับหัวข้อ 25 คะแนน **"แก้ไข ปรับปรุง หรือเพิ่มฟังก์ชันตามที่กรรมการกำหนดได้ทันที"**
ทุกข้อเปิดโค้ดจริงตรวจแล้วเมื่อ 1 ต.ค. 2569 — อ้างด้วย **ชื่อไฟล์ + ชื่อฟังก์ชัน/ตัวแปร** (ไม่อ้างเลขบรรทัด เพราะเลขบรรทัดเปลี่ยนได้)
วิธีหา: เปิดไฟล์ใน VS Code แล้วกด `Ctrl+F` พิมพ์ชื่อฟังก์ชัน/ตัวแปรที่ระบุ

## 0. ท่ามาตรฐาน 5 ขั้น เมื่อกรรมการสั่งแก้ (พูดออกเสียงตามนี้ทุกครั้ง)

1. **ทวนโจทย์** — "อาจารย์ต้องการให้ … ใช่ไหมครับ" (กันเข้าใจผิด และได้เวลาคิด)
2. **บอกก่อนว่าจะแก้ที่ไหน** — "เรื่องนี้เป็นกฎธุรกิจ อยู่ฝั่ง backend ที่ไฟล์ … ฟังก์ชัน … และหน้าจออ่านค่าเดียวกันที่ไฟล์ …"
3. **แก้ให้น้อยที่สุด** — แก้ค่าคงที่/เงื่อนไขบรรทัดเดียว ไม่เขียนใหม่ทั้งฟังก์ชัน
4. **บอกผลกระทบ** — "ข้อความ error ใช้ค่าคงที่ตัวเดียวกันจึงเปลี่ยนตาม · เทส phase… จะ fail เพราะเทสคาดค่าเดิม ต้องแก้เทสตาม"
5. **พิสูจน์** — restart backend (ถ้าแก้ backend) → เปิดหน้าเว็บ/ยิง curl/รันเทสให้ดู

> **ความปลอดภัยของข้อมูลเดโมตอนฝึก:** ฐานข้อมูลในเครื่อง (`ProjectEnd` 928 คน) คือข้อมูลที่จะใช้เดโมวันสอบ
> ยิง `curl` ใส่ได้เฉพาะ **GET** (อ่านอย่างเดียว) และคำขอที่ **ควรถูกปฏิเสธ** (ได้ 400/403/429 = ไม่มีอะไรถูกบันทึก)
> คำขอที่บันทึกจริง (สร้าง/แก้/ยืนยัน) ให้พิสูจน์ด้วย `npm run test:clean` (ฐานข้อมูลชั่วคราว) แทน
>
> **จำ 2 ข้อนี้ให้ขึ้นใจ**
> - แก้ `backend/` ต้อง **ปิดแล้วเปิด `npm start` ใหม่** (ไม่มี auto-reload) · แก้ `frontend/` Vite เปลี่ยนให้เองทันที
> - ฝึกเสร็จทุกครั้งให้คืนโค้ด: `git checkout -- <ไฟล์ที่แก้>` (ห้าม `git add .`)

# A. ไฟล์หลักฐาน

## A1 ★ "เปลี่ยนให้แนบได้สูงสุด 3 ไฟล์ (จากเดิม 5)"
- **แก้ 2 จุดให้ตรงกัน**
  - Backend `backend/src/modules/certificates/certificates.controller.js` → ค่าคงที่ `MAX_FILES_PER_RESULT`
  - Frontend `frontend/src/design/evidenceFiles.js` → ค่าคงที่ `MAX_EVIDENCE_FILES`
```js
const MAX_FILES_PER_RESULT = 3;        // backend (เดิม 5)
export const MAX_EVIDENCE_FILES = 3;   // frontend (เดิม 5)
```
- **ทำไมต้อง 2 จุด:** frontend กันไว้เพื่อบอกผู้ใช้ทันที แต่ **ตัวที่กันจริงคือ backend** (ยิง API ตรงก็เกินไม่ได้)
- **กระทบอะไร:** ข้อความทุกจุดใช้ค่าคงที่ตัวนี้อยู่แล้ว จึงเปลี่ยนตามเอง (`tooManyFilesError` ฝั่ง backend, `{max}` ใน `i18n.js` ฝั่งหน้าจอ) · ที่ **ไม่เปลี่ยนเอง** คือคู่มือในระบบ `userManual.jsx` (เขียนคำว่า "5 ไฟล์" ไว้ 3 จุด) · เทส `phase25`, `phase26`, `phase27` และเทสหน้าเว็บ (WEB-09) คาดว่า 5 ไฟล์ → จะ fail จนกว่าจะแก้เทส
- **พิสูจน์:** restart backend → เข้าเป็นนักศึกษา → หน้ากรอกผลสอบ เห็น "แนบแล้ว 0 จาก 3 ไฟล์" → เลือก 4 ไฟล์พร้อมกัน ไฟล์ที่ 4 ขึ้นข้อความแดง
- **พูดตอบ:** "ตัวเลขนี้เป็นค่าคงที่ที่เดียวต่อฝั่ง ข้อความอ้างค่าคงที่ จึงไม่ต้องไล่แก้ข้อความ"

## A2 ★★ "ให้รับเฉพาะ PDF เหมือนเดิม ไม่รับรูปภาพ"
ต้องแก้ **3 ด่านฝั่ง backend + 2 จุดฝั่ง frontend** (อธิบายได้ว่าแต่ละด่านกันอะไร)
1. `backend/src/middlewares/upload.js` → `EVIDENCE_TYPES` (ด่านชนิดที่เบราว์เซอร์บอกมา)
```js
const EVIDENCE_TYPES = ["application/pdf"];
// และข้อความใน fileFilter: "รองรับเฉพาะไฟล์ PDF"
```
2. `backend/src/modules/certificates/certificates.controller.js` → `FILE_SIGNATURES` (ด่านตรวจเนื้อไฟล์จริง) เหลือแถวเดียว
```js
const FILE_SIGNATURES = [
  { fileType: "pdf", bytes: [0x25, 0x50, 0x44, 0x46, 0x2d] },
];
// และข้อความใน upload(): "ไฟล์ที่แนบต้องเป็น PDF เท่านั้น กรุณาเลือกไฟล์ใหม่"
```
3. `frontend/src/design/evidenceFiles.js` → `EVIDENCE_ACCEPT`
```js
export const EVIDENCE_ACCEPT = '.pdf,application/pdf';
```
4. `frontend/src/design/examFormReal.jsx` → ฟังก์ชัน `addFiles` เงื่อนไขแรก
```js
if (kind !== 'pdf') {          // เดิม: if (kind === '')
  problems.push(tt('examform.fileWrongType', { name: file.name }));
}
```
5. `frontend/src/design/i18n.js` → `examform.attachHint`, `examform.fileWrongType` (ทั้ง TH และ EN) แก้คำว่า "JPG, PNG" ออก
- **กระทบอะไร:** ไฟล์รูปที่แนบไว้แล้วในระบบยังเปิดดูได้ (`serveFile` อ่าน `file_type` ที่เก็บไว้) · เทส `phase25/26/27` ที่แนบ JPG/PNG จะ fail
- **พิสูจน์:** แนบไฟล์ `.png` บนหน้าเว็บ → ข้อความแดง · ยิงตรง: `curl -b cj_student.txt -F "file=@a.png" -F "certificate_type=exam_result" localhost:3000/api/exam-results/<id>/certificates` → 400
- **พูดตอบ:** "ด่าน 1 ดูชนิดที่เบราว์เซอร์บอก (ปลอมได้) ด่าน 2 อ่านไบต์ต้นไฟล์จริง — ต้องแก้ทั้งคู่ ไม่งั้นเปลี่ยนนามสกุลรูปเป็น .pdf ก็หลุดด่าน 1 แต่ไม่หลุดด่าน 2"

## A3 ★ "ลดขนาดไฟล์สูงสุดเป็น 5 MB"
- Backend `backend/src/middlewares/upload.js` → `uploadEvidence` → `limits: { fileSize: 5 * 1024 * 1024 }`
- Frontend `frontend/src/design/evidenceFiles.js` → `MAX_FILE_SIZE_MB = 5`
- **กระทบอะไร:** ข้อความเกินขนาดฝั่ง backend มาจาก `middlewares/errorHandler.js` (`LIMIT_FILE_SIZE` → "ไฟล์ใหญ่เกินกำหนด…") ไม่ระบุตัวเลข จึงไม่ต้องแก้ · `userManual.jsx` เขียน "10 MB" ไว้ ต้องแก้คำ · เทส `phase26` (PH26-08 ไฟล์ 10 MB + 1 KB) ยังผ่าน เพราะไฟล์นั้นยังใหญ่เกินอยู่
- **พิสูจน์:** เลือกไฟล์ 6 MB บนหน้าเว็บ → ข้อความ "…เกินกำหนด 5 MB"

## A4 ★★ "ห้ามยืนยันผลสอบ ถ้าใบนั้นไม่มีไฟล์หลักฐานแนบ" — **ระบบทำไว้แล้ว (5 ต.ค. 2569)** ใช้เป็นโจทย์ "ชี้โค้ด + อธิบาย" และโจทย์ดัดแปลง
- **ตอนนี้ทำงานยังไง:** `backend/src/modules/examResults/examResults.controller.js` → `reviewExamResult` → ฟังก์ชัน `checkBeforeSave` (รันใน transaction ที่ล็อกแถวใบแล้ว) ถ้า `staff_status === APPROVED` และ `current.certificates.length === 0` → `409` "ใบนี้ยังไม่มีไฟล์หลักฐานแนบ ยืนยันไม่ได้ กรุณาตีกลับ…" · ตีกลับ (reject) ไม่ถูกบังคับ
- **ทำไมตรวจตอนยืนยัน ไม่ใช่ตอนส่ง:** ใบใหม่ต้องสร้างใบก่อนถึงจะมีเลขใบไว้แนบไฟล์ → จุดบังคับที่เหมาะคือตอนยืนยัน · และต้องตรวจ "ใน transaction" ไม่ใช่ก่อนหน้า เพราะนักศึกษาอาจลบไฟล์ระหว่างที่เจ้าหน้าที่กด
- **หน้าจอ:** `studentDetailReal.jsx` → ตัวแปร `hasEvidenceFile` ปิดปุ่มยืนยัน + ข้อความ `officer.detail.confirmNeedsFile` (กฎจริงอยู่ backend หน้าจอแค่ช่วยไม่ให้กดผิด)
- **โจทย์ดัดแปลงที่กรรมการอาจให้แก้สด:** "ต้องมีอย่างน้อย **2 ไฟล์** ถึงยืนยันได้" → เปลี่ยน `=== 0` เป็น `< 2` ในด่านนั้น และปรับข้อความ · **กระทบ:** เทสที่แนบไฟล์เดียว (ตัวช่วย `tests/autoEvidence.mjs`) จะ fail ตรงขั้นยืนยัน = หลักฐานว่าแก้ถูก แล้วแก้เทสให้แนบ 2 ไฟล์ · พิสูจน์: `ONLY=phase33 npm run test:clean` (ข้อ B-03)

## A5 ★★★ "ให้เจ้าหน้าที่ลบไฟล์หลักฐานของนักศึกษาได้"
- **ตอบก่อนแก้ (ได้คะแนนตรงนี้):** "ตอนนี้ตั้งใจไม่ให้ลบ — หลักฐานเป็นของนักศึกษา ถ้าไฟล์ผิดให้ตีกลับ จะได้มีประวัติใน `review_logs`. ถ้าต้องการจริงต้องแก้ 3 จุด"
1. `backend/src/modules/certificates/certificates.routes.js` → `router.delete("/:id", authenticate, requireRole("student", "officer"), remove);`
2. `certificates.controller.js` → `remove` : ฟังก์ชัน `ensureCanChangeEvidence` ตรวจว่า "เป็นเจ้าของใบ" ซึ่งเจ้าหน้าที่ไม่ผ่านแน่นอน จึงต้องแยกทาง

}

# H. ฐานข้อมูล

> แก้ `prisma/schema.prisma` **ต้องได้รับอนุญาตจากเจ้าของงานก่อน** และในเครื่องนี้ `prisma migrate dev` ใช้ไม่ได้ (ผู้ใช้ฐานข้อมูลไม่มีสิทธิ์สร้าง shadow database) — ต้องเขียนไฟล์ migration เองแล้ว `npx prisma migrate deploy`
> **ตอนสอบ:** อธิบายขั้นตอนให้ครบและแก้ไฟล์ให้ดูได้ แต่ **อย่ารัน migrate ใส่ฐานข้อมูลจริง** ถ้ายังไม่ได้สำรอง

## H1 ★★★ "เพิ่มช่อง 'ชื่อเล่น' ของนักศึกษา" (ทั้งเส้นจากฐานข้อมูลถึงหน้าจอ)
1. `backend/prisma/schema.prisma` → `model Student` เพิ่ม `nickname String? @db.VarChar(50)`
2. สร้างโฟลเดอร์ `prisma/migrations/<ปีเดือนวันเวลา>_add_student_nickname/` + ไฟล์ `migration.sql`
```sql
ALTER TABLE "students" ADD COLUMN "nickname" VARCHAR(50);
```
3. `npx prisma migrate deploy` → `npx prisma generate`
4. `student.controller.js` → `PROFILE_TEXT_FIELDS` เพิ่ม `["nickname", "ชื่อเล่น", 50]` (ได้การตรวจ "ไม่ว่าง + ความยาว" ทันที) → ใน `completeProfile`/`update` แกะ `nickname` ออกมาแล้วส่งต่อ (ฝั่ง `update` ใส่ใน `studentData`)
5. `student.repository.js` → `completeProfile` (ในก้อน `student: { create: { ... } }`) เพิ่ม `nickname`
6. Frontend: `completeProfile.jsx` (ช่องกรอก), `studentDetailReal.jsx` (แสดง + ฟอร์มแก้ไข `editForm`)
7. เอกสาร: `BACKEND_GUIDE.md` + data dictionary ในรายงาน (บท 3.4)
- **ทำไม `String?` (ว่างได้):** แถวเก่าไม่มีค่า — ถ้าบังคับไม่ว่าง คำสั่ง `ADD COLUMN` จะล้มกับข้อมูลเดิม
- **ระวัง:** `PROFILE_TEXT_FIELDS` กับ `requireAll = true` ทำให้ช่องใหม่ "บังคับกรอก" ตอนตั้งโปรไฟล์ครั้งแรก — ถ้าไม่ต้องการบังคับ ต้องตรวจแยก

## H2 ★★★ "รหัสวิชาห้ามซ้ำ ให้กันที่ฐานข้อมูลด้วย"
- ตอนนี้กันที่โค้ดอย่างเดียว (`subjects.controller.js → ensureCodeFree` — คอมเมนต์บอกว่า schema ไม่ได้ตั้ง unique)
1. `schema.prisma` → `model Subject` : `subject_code String @unique @db.VarChar(10)`
2. `migration.sql`
```sql
CREATE UNIQUE INDEX "subjects_subject_code_key" ON "subjects"("subject_code");
```
- **ต้องเช็คก่อน:** ถ้ามีรหัสซ้ำอยู่แล้วในตาราง คำสั่งนี้จะล้ม → ต้องแก้ข้อมูลซ้ำก่อน
- **ผลพลอยได้:** ถ้าสองคนเพิ่มวิชารหัสเดียวกันพร้อมกัน ฐานข้อมูลปฏิเสธคนหลัง (Prisma โยน `P2002`) → `errorHandler.js` แปลงเป็น 409 ข้อความไทยให้อยู่แล้ว
- **พูดตอบ:** "กันที่โค้ดได้ข้อความที่อ่านง่าย กันที่ฐานข้อมูลได้ความแน่นอนเมื่อมีสองคำขอพร้อมกัน — ตัวอย่างเดียวกับ `@@unique([student_id, round_id])` ของใบผลสอบ"
