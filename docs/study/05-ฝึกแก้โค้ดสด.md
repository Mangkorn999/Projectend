# 05 — ฝึกแก้โค้ดสด (หัวข้อ "เพิ่ม/แก้ฟังก์ชันตามที่กรรมการสั่ง" — 25 คะแนน)

กรรมการจะไม่ถามว่า "จำโค้ดได้ไหม" แต่จะสั่ง เช่น **"ลองเพิ่มช่องนี้หน่อย" / "ถ้าอยากเปลี่ยนกฎนี้แก้ตรงไหน"**
สิ่งที่ตัดสินคะแนนคือ **หาไฟล์ถูกเร็ว + รู้ว่าแก้แล้วกระทบอะไร + ทดสอบให้ดู**

> **อัปเดต 1 ต.ค.:** แผนที่ครบ 45 โจทย์ (ไฟล์ + ฟังก์ชัน + ผลกระทบ + วิธีพิสูจน์) อยู่ที่ **`08`** · แบบฝึกพร้อมเฉลย 29 ข้ออยู่ที่ `11` · ไฟล์นี้เก็บโจทย์ที่อธิบายละเอียดแบบลงมือ (ข้อ 16–18 เพิ่มใหม่เรื่องหลายไฟล์/แก้หลังปิดรอบ)

## วิธีฝึก
1. อ่านโจทย์ → **ปิดเฉลย** → เปิดโค้ดจริงลงมือแก้เอง จับเวลา (ข้อละ ≤ 10 นาที)
2. ทุกข้อต้อง "พิสูจน์ว่าได้ผล" — รันแล้วเห็นผล (curl / เปิดหน้าเว็บ / รันเทส) ไม่ใช่แค่แก้แล้วบอกว่าเสร็จ
3. ฝึกเสร็จคืนโค้ดด้วย `git checkout -- <ไฟล์ที่แก้>` ทีละไฟล์ (ดูรายชื่อจาก `git status`) — **ห้าม `git checkout .` หรือ `git add .`** เพราะในเครื่องมีงานที่ยังไม่ commit ของคนอื่นปนอยู่
4. **ข้อมูลเดโม (928 คน) คือข้อมูลที่จะใช้วันสอบ:** curl ได้เฉพาะ GET และคำขอที่ควรถูกปฏิเสธ (400/403/429) · คำขอที่บันทึกจริงให้พิสูจน์ด้วย `npm run test:clean`

## เครื่องมือที่ต้องคล่อง (กรรมการให้ดูตอนแก้สด)
| ต้องการ | ทำยังไง |
|---|---|
| หาโค้ดที่เกี่ยวข้อง | VS Code: `Ctrl+Shift+F` ค้นข้อความบนหน้าจอ (เช่น "ส่งออกข้อมูล") → ได้ key i18n → ค้น key นั้น → เจอไฟล์ |
| ดูว่า API ตอบอะไร | เบราว์เซอร์ F12 → แท็บ **Network** → คลิก request → Response |
| ทดสอบ API ตรง ๆ | login ก่อนเก็บ cookie: `curl -c cj.txt -X POST localhost:3000/api/auth/login -H "Content-Type: application/json" -d "{\"psu_passport_id\":\"456\",\"password\":\"456\"}"` แล้วใช้ `-b cj.txt` กับคำสั่งถัดไป |
| ดู error ฝั่ง backend | terminal ที่รัน `npm start` (ต้อง restart เมื่อแก้ backend — ไม่มี auto-reload) หรือใช้ `npx nodemon src/server.js` |
| ดู DB ตรง ๆ | `npx prisma studio` (เปิดที่ localhost:5555) |
| ดูว่า frontend แก้แล้วเปลี่ยนไหม | Vite มี hot reload อัตโนมัติ (ไม่ต้อง restart) |

## ระดับ 1 — แก้ค่า/ข้อความ (2–5 นาที)

### ข้อ 1. เปลี่ยนจำนวนแถวต่อหน้าของตารางนักศึกษา เป็น 25
- **หา:** `frontend/src/design/officerStudentsReal.jsx` บรรทัด `const per = 10;`
- **แก้:** `const per = 25;`
- **พิสูจน์:** เปิดหน้า "ข้อมูลนักศึกษา" → ใต้ชื่อหน้าเห็น "แสดง 25 จาก ..." ; หน้า 2 = 50
- **พูดตอบ:** "ตัวนับใต้ชื่อหน้าคำนวณจาก `per` ตัวเดียวกัน จึงเปลี่ยนตามเอง" (ไม่ต้องแก้หลายที่)

### ข้อ 2. เปลี่ยนอายุ token จาก 1 วัน เป็น 2 ชั่วโมง
- **หา:** `backend/src/controllers/authController.js` — **ต้องแก้ 2 จุดให้ตรงกัน:**
  - `maxAge: 24 * 60 * 60 * 1000` (อายุ cookie) → `2 * 60 * 60 * 1000`
  - `{ expiresIn: "1d" }` (อายุ JWT) → `{ expiresIn: "2h" }`
- **ทำไมต้องแก้ 2 จุด:** ถ้า cookie อยู่นานกว่า token = cookie ค้างแต่ token หมดอายุ (login แล้วโดน 401 งง ๆ)
- **พิสูจน์:** restart backend → login → F12 → Application → Cookies → ดู Expires
- **ข้อควรระวัง:** ผู้ใช้ที่ login อยู่ก่อนแก้ยังใช้ token เก่าได้จนหมดอายุเดิม

### ข้อ 3. ให้ login ผิดได้แค่ 5 ครั้ง/15 นาที
- **หา:** `backend/src/modules/auth/auth.routes.js` — `rateLimit({ windowMs: 15*60*1000, max: 10, keyField: "psu_passport_id" })` → `max: 5`
- **พิสูจน์:** รีสตาร์ท backend (ตัวนับอยู่ใน memory) → ยิง login รหัสผิด 6 ครั้ง → ครั้งที่ 6 ได้ **429** "ลองมากเกินไป กรุณาลองใหม่ใน N วินาที"
- **พูดตอบ:** "ตัวนับนับแยกตามรหัสผู้ใช้ กันคนเดารหัสของบัญชีเดียว; อีกชั้นนับตาม IP กันหมุนเปลี่ยนรหัสผู้ใช้"

### ข้อ 4. เปลี่ยนคำบนปุ่ม / เพิ่มข้อความ
- **หา:** ค้นข้อความบนจอใน `i18n.js` (เช่น 'ส่งออกข้อมูล') → แก้ทั้ง TH และ EN
- **พิสูจน์:** รีเฟรชหน้า (Vite เปลี่ยนให้เอง) · สลับ TH/EN ดูทั้งสองภาษา
- **พูดตอบ:** "ข้อความทั้งหมดอยู่ที่ `i18n.js` ที่เดียว ผ่านฟังก์ชัน `t(lang, key)`"

### ข้อ 5. เปลี่ยนสีป้ายสถานะ "ยืนยันแล้ว"
- **หา:** `frontend/src/design/styles.css` ค้น `.badge.ok` / ตัวแปร `--status-ok-bg`, `--status-ok-fg` ใน `:root`
- **พิสูจน์:** ดูหน้าที่มีป้ายสถานะ (ตารางนักศึกษา)
- **พูดตอบ:** "สี/ขนาดกลางเป็น CSS variable ใน `:root` เปลี่ยนที่เดียวเปลี่ยนทั้งระบบ"

## ระดับ 2 — แก้ logic/กฎ (5–10 นาที)

### ข้อ 6. เปลี่ยนหลักสูตรเป็น 5 ปี (ปีจบ = ปีเข้า + 5)
- **หา:** `backend/src/utils/academicYear.js` → `return entryYear + 4;` → `+ 5`
- **รู้ว่าต้องกระทบอะไร:** `calcGraduationYear` ใช้ตอน import/สร้างนักศึกษา/complete-profile และใน `validateGraduationYear` (ปีที่พิมพ์มาต้อง ≥ ค่าที่คำนวณ); ข้อความ error/คู่มือที่บอก "ปีที่เข้า + 4" ต้องแก้ตาม
- **เช็คเทส:** `ONLY=phase16 npm run test:clean` จะ fail (เทสเดิมสมมติ +4) — **นี่แหละคือเหตุผลที่มีเทส** ตอบกรรมการได้ว่า "แก้กฎแล้วเทสบอกว่าอะไรกระทบ"
- **พูดตอบ:** "กฎปีจบอยู่ไฟล์เดียว ใช้ซ้ำ 3 จุด (import, เพิ่มทีละคน, แก้ข้อมูล)"

### ข้อ 7. เพิ่ม validation: เบอร์โทรต้องเป็นตัวเลข 10 หลักขึ้นต้น 0
- **หา:** `backend/src/modules/students/student.controller.js` ค้น `PHONE_PATTERN` (ตอนนี้ `/^[0-9+\-\s]{8,20}$/`)
- **แก้:** `const PHONE_PATTERN = /^0\d{9}$/;` (+ แก้ข้อความ error ที่ `httpError("เบอร์โทรไม่ถูกต้อง", 400)` ให้บอกรูปแบบ)
- **ข้อควรระวัง:** `createUser` ของ officer/executive ใช้การตรวจคนละที่ (`users.controller.js`) — ตอบได้ว่า "ตอนนี้ผู้ใช้ภายในไม่ได้ตรวจรูปแบบเบอร์ ต้องแก้แยก" (รู้ข้อจำกัดของตัวเอง = คะแนน)
- **พิสูจน์:** `curl` ยิง `PATCH /api/students/:id` ด้วย `{"phone":"abc"}` → 400 (ถูกปฏิเสธ ไม่มีอะไรถูกบันทึก) · กรณีเบอร์ถูกต้อง พิสูจน์ด้วย `ONLY=phase20 npm run test:clean` แทนการแก้ข้อมูลเดโม

### ข้อ 8. ให้ล็อกหน้ากรอกผลสอบถ้านักศึกษาส่งไปแล้ว 3 ครั้งในรอบเดียว (แก้ได้แค่ 3 ครั้ง)
- **แนวคิด:** ตอนนี้แก้ทับได้ไม่จำกัดจนกว่าจะยืนยัน → ต้องนับจำนวนครั้ง
- **ตัวเลือกง่ายสุด:** นับจาก `review_logs`? ไม่ได้ (ไม่มี log ตอนส่ง) → ต้อง **เพิ่มคอลัมน์** `submit_count Int @default(1)` ใน `exam_results` (ดูข้อ 11) แล้ว `+1` ใน `resubmitWithSubjects` และ `throw httpError("แก้ไขได้ไม่เกิน 3 ครั้ง", 409)` เมื่อ ≥ 3 ที่ `create`
- **จุดที่ฝึกคือ:** บอกให้ถูกว่า "ต้องแตะ 3 ที่: schema+migration, repository, controller" ก่อนลงมือ

### ข้อ 9. ผู้บริหารเห็นเมนู "ข้อมูลนักศึกษา" (เพิ่มหน้าให้ role หนึ่ง — ใช้ได้จริงถ้าอาจารย์ขอ)
ต้องแก้ **ทั้งสองฝั่ง** ตามลำดับนี้ (ตอบให้ได้ว่าทำไมต้องครบ):
1. **Backend (กันข้อมูลจริง):** `students.routes.js` → `router.get("/", ...)` และ `router.get("/:id", ...)` เพิ่ม `"executive"` (เช่น `requireRole("officer","reviewer","executive")`) และ `examResults.routes.js` → `GET /` เพิ่ม `"executive"` (ต้อง **ไม่** เพิ่มใน POST/PATCH/DELETE ใด ๆ — ผู้บริหารต้องอ่านอย่างเดียว)
2. **Frontend ตารางสิทธิ์หน้า:** `app.jsx` → `ROLE_PAGES.executive` เพิ่ม `'students'`, `'detail'`
3. **เมนู:** `app.jsx` `executive: [...]` เพิ่ม `{ k:'students', label: translate(lang,'nav.executive.students'), icon:'users' }`
4. **หน้าจอ:** ส่ง `readonly` ให้ `OfficerStudentsReal`/`StudentDetailReal` (มี prop `readonly` อยู่แล้ว ซ่อนปุ่มลบ/แก้/ส่งออก)
5. **เทส:** แก้ smoke test ที่คาดว่าผู้บริหารได้ 403 (`phase4-6` PH06-07/08, `phase22`, `phase26` PH26-19) ให้ตรงกับกฎใหม่
- **พูดตอบ:** "ซ่อนเมนูอย่างเดียวไม่พอ ต้องเปิดสิทธิ์ที่ backend และยังปิดการเขียนทุกเส้น; ตอนนี้ตัดสินใจปิดไว้เพื่อ data minimization"

## ระดับ 3 — เพิ่ม endpoint / ฟิลด์ / ตัวกรอง (10–20 นาที)

### ข้อ 10. เพิ่ม endpoint `GET /api/rounds/:id/summary` — จำนวนใบผลสอบในรอบแยกตามสถานะ
ตัวอย่างผลลัพธ์: `{ round_id: 4, total: 58, pending: 30, approved: 17, rejected: 11 }`

**ขั้นตอน (ตามรูปแบบ routes → controller → repository):**

1) `backend/src/modules/examResults/examResults.repository.js` — เพิ่มฟังก์ชัน (repository คุย Prisma เท่านั้น):
```js
export const countByStaffStatus = async (roundId) => {
  const rows = await prisma.examResult.groupBy({
    by: ["staff_status"],
    where: { round_id: Number(roundId) },
    _count: { _all: true },
  });
  // แปลง [{ staff_status:"approved", _count:{_all:17} }, ...] เป็น { approved:17, ... }
  const counts = { pending: 0, approved: 0, rejected: 0 };
  for (const row of rows) counts[row.staff_status] = row._count._all;
  return counts;
};
```
2) `backend/src/modules/rounds/rounds.controller.js` — เพิ่ม controller (มี `examRepo` import อยู่แล้ว):
```js
export const getSummary = async (req, res, next) => {
  try {
    const round = await roundsRepo.findById(req.params.id);
    if (!round) throw httpError("ไม่พบรอบการกรอกนี้", 404);
    const counts = await examRepo.countByStaffStatus(round.round_id);
    const total = counts.pending + counts.approved + counts.rejected;
    res.json({ success: true, data: { round_id: round.round_id, total, ...counts } });
  } catch (err) {
    next(err);
  }
};
```
3) `backend/src/modules/rounds/rounds.routes.js` — เพิ่มบรรทัดเดียว (และ import `getSummary`):
```js
router.get("/:id/summary", authenticate, requireRole("officer", "executive"), getSummary);
```
4) **restart backend** แล้วทดสอบ:
```bash
curl -b cj.txt localhost:3000/api/rounds/4/summary        # → {"success":true,"data":{...}}
curl -b cj.txt localhost:3000/api/rounds/99999/summary    # → 404 ข้อความไทย
# ไม่ login → 401 · ล็อกอินเป็นนักศึกษา → 403
```
- **จุดที่กรรมการจะถาม:** "ทำไมใส่ requireRole?" (ผู้บริหารดูภาพรวมได้ แต่นักศึกษาห้าม) · "ทำไมคืน 0 ให้สถานะที่ไม่มีแถว?" (groupBy ไม่คืนกลุ่มที่ว่าง → ต้องตั้งค่าเริ่มต้นเอง)
- **ผลลัพธ์นี้ตรวจแล้วกับ DB จริงของโปรเจกต์:** รอบตัวอย่างได้ 30 รอตรวจ / 17 ยืนยัน / 11 ตีกลับ

### ข้อ 11. เพิ่มคอลัมน์ใหม่ในตาราง (เช่น `nickname` ของนักศึกษา) — ทั้งเส้นจาก DB ถึงหน้าจอ
1) **Schema** `backend/prisma/schema.prisma` ใน `model Student` เพิ่ม `nickname String? @db.VarChar(50)`
2) **Migration** (`prisma migrate dev` ใช้ไม่ได้ในเครื่องนี้ — user DB ไม่มีสิทธิ์สร้าง shadow database):
   - สร้างโฟลเดอร์ `prisma/migrations/<เวลา>_add_student_nickname/` แล้วสร้าง `migration.sql`:
     ```sql
     ALTER TABLE "students" ADD COLUMN "nickname" VARCHAR(50);
     ```
   - รัน `npx prisma migrate deploy` แล้ว `npx prisma generate`
   - (เขียน SQL เองได้ตรง ๆ เพราะเป็นแค่ ADD COLUMN ที่ nullable; หรือใช้ `prisma migrate diff ... --script` ให้ช่วยสร้างแล้วตรวจก่อนรัน)
3) **Backend:** `student.controller.js` เพิ่ม `nickname` ใน `PROFILE_TEXT_FIELDS` (มี validation ความยาวให้) · `student.repository.js` ใส่ใน `select` ของ `findById`/`update`/`completeProfile` data
4) **Frontend:** `completeProfile.jsx` เพิ่มช่องกรอก + `studentDetailReal.jsx` แสดง/แก้ไข
5) **ส่งออก:** เพิ่มคอลัมน์ใน `exportStudents` (ข้อ 12)
6) อัปเดต `BACKEND_GUIDE.md` (กฎของโปรเจกต์: แก้ backend ต้องอัปเดตเอกสารในคอมมิตเดียวกัน) และ data dictionary ในรายงาน (บท 3.4)
- **ทำไม nullable:** แถวเก่าที่มีอยู่แล้วไม่มีค่า — ถ้าบังคับ NOT NULL migration จะพังกับข้อมูลเดิม
- **พูดตอบ:** "เปลี่ยน schema ที่ `schema.prisma` ที่เดียวเป็นต้นทางความจริง แล้ว migration ทำให้ทุกเครื่องมีโครงเหมือนกัน"

### ข้อ 12. เพิ่มคอลัมน์ "จำนวนรอบที่ส่ง" ในไฟล์ Excel ข้อมูลนักศึกษา
- **หา:** `student.controller.js → exportStudents` (ฟังก์ชันเดียวมี `rows` กับ `columns`)
- **แก้ 2 จุด:**
  - ใน `rows` (ตอน `students.map`): เพิ่ม `round_count: s.exam_results.length,`
  - ใน `columns` ของ `studentSheet`: เพิ่ม `{ header: "จำนวนรอบที่ส่ง", key: "round_count", width: 14, type: "number" },`
- ไม่ต้องแก้ repository เพราะ `findForExport` ดึง `exam_results` มาอยู่แล้ว
- **พิสูจน์:** รีสตาร์ท backend → กดส่งออกข้อมูลนักศึกษา → เปิด Excel ดูคอลัมน์ใหม่ (`type:"number"` ทำให้เป็นตัวเลขจริง)
- **พูดตอบ:** "ทุกเซลล์เป็นข้อความ ยกเว้นคอลัมน์ที่ระบุ type number — กัน Excel ตัดเลข 0 หน้าเบอร์โทร"

### ข้อ 13. เพิ่มตัวกรอง "เฉพาะคนที่ส่งแล้ว" ในหน้าข้อมูลนักศึกษา
- **หา:** `officerStudentsReal.jsx` — ดูว่าตัวกรอง "สถานะ" (`status`) กรองยังไง (อยู่ในก้อน `filtered = students.filter(...)`)
- **แนวคิด:** ตัวกรองทั้งหมดทำฝั่งหน้าจอ: เพิ่ม state + เพิ่มเงื่อนไขใน `.filter` + เพิ่ม `<Select>` ในแถบตัวกรอง + เพิ่มใน `resetKey` ของการแบ่งหน้า/`useEffect(() => setPage(0), [...])` เพื่อเด้งกลับหน้า 1
- **จุดที่หลายคนลืม:** เพิ่มตัวแปรใหม่ในรายการ dependency ที่รีเซ็ตหน้า — ไม่งั้นกรองแล้วค้างอยู่หน้า 7 เห็นหน้าว่าง

## ระดับ 4 — วิเคราะห์/แก้บั๊ก (ข้อสอบจริงมักเป็นแนวนี้)

### ข้อ 14. "หน้าเว็บขึ้น error / ข้อมูลไม่มา" — ไล่หาสาเหตุ 4 ขั้น (สำคัญ ฝึกพูดเป็นลำดับ)
1. **เปิด F12 → Network** ดู request ที่สีแดง: status code อะไร?
   - 401 → cookie หมดอายุ/ไม่ได้ login · 403 → role ไม่พอ · 400 → ส่งข้อมูลผิด (ดู `message` ใน Response) · 404 → URL/ไอดีผิด · 500 → backend พัง
2. **ดู terminal backend** — 500 จะมี stack trace บอกไฟล์/บรรทัด
3. **ยิง API ตรงด้วย curl** เพื่อแยกว่าบั๊กอยู่ frontend หรือ backend (curl ได้ถูกแต่หน้าเว็บผิด = บั๊ก frontend)
4. **ดู DB** ด้วย `prisma studio` ว่าข้อมูลที่คาดหวังมีจริงไหม
- **พูดตอบ:** "ผมแบ่งชั้น: frontend → เครือข่าย → backend → DB แล้วตัดทีละชั้น"

### ข้อ 15. โจทย์วิเคราะห์ที่กรรมการชอบให้ (ตอบปากเปล่า + ชี้โค้ด)

## ระดับ 5 — โจทย์ใหม่จากการเปลี่ยนแปลง 1 ต.ค.

### ข้อ 16. ลดจำนวนไฟล์แนบเป็น 3 (★ ≤ 3 นาที)
- **หา:** backend `certificates.controller.js → MAX_FILES_PER_RESULT` · frontend `evidenceFiles.js → MAX_EVIDENCE_FILES`
- **แก้:** ทั้งคู่เป็น `3` → restart backend
- **พิสูจน์:** หน้ากรอกผลของนักศึกษาเขียน "แนบแล้ว 0 จาก 3 ไฟล์" · เลือก 4 ไฟล์ ไฟล์ที่ 4 ขึ้นข้อความแดง (ไม่ต้องกดส่ง)
- **พูดตอบ:** "ข้อความใช้ค่าคงที่ จึงเปลี่ยนตามเอง · ที่ต้องแก้มือคือคู่มือ `userManual.jsx` · เทส phase25/26/27 + WEB-09 จะ fail เพราะคาด 5"

### ข้อ 17. ปิดความสามารถ "แก้ใบที่ถูกตีกลับหลังปิดรอบ" (★ ≤ 5 นาที)
- **หา:** `examResults.service.js → findSubmittableRound`
- **แก้:** หลัง `if (activeRound) { return ... }` ใส่ `return null;` (ขั้น 2–3 ไม่ทำงาน)
- **ไม่ต้องแก้ที่อื่น** เพราะ `create`, `getActive`, `ensureCanChangeEvidence` เรียกฟังก์ชันนี้ตัวเดียว · หน้าเว็บอ่าน `can_fix_rejected` ซึ่งจะเป็น `false` เอง
- **พิสูจน์:** `ONLY=phase25 npm run test:clean` → fail ที่ PH25-05 (แก้ใบที่ถูกตีกลับหลังปิดรอบ) = ยืนยันว่าแก้ถูกจุด
- **พูดตอบ:** "นี่คือข้อดีของการรวมกฎไว้ฟังก์ชันเดียว — เปลี่ยนนโยบายที่เดียว 3 ทางเปลี่ยนตาม"

### ข้อ 18. อธิบายบั๊ก B1 พร้อมชี้ 3 จุดที่แก้ (★★ ตอบปากเปล่า ≤ 3 นาที)
- **เล่าเหตุการณ์:** รอบ 1 รอตรวจ (วิชา A ผ่าน) → เปิดรอบ 2 นักศึกษาส่ง (A ยกมา `carried_forward`) → ตีกลับใบรอบ 1 → ยืนยันใบรอบ 2 → A ถูกนับว่าผ่าน (ล็อกรอบ 3 + "ผ่านภายในปีแรก" สูงเกิน)
- **ชี้โค้ด 3 จุด (เงื่อนไขเดียวกัน "ไม่นับแถวยกมา"):** `examResults.repository.js → findPassedSubjectIds` (`carried_forward: false`) · `dashboard.repository.js → findEligibleWithPassedSubjects` (`carried_forward: false`) · `dashboard.service.js → addConfirmedRealPasses` (`if (sr.carried_forward) continue;`)

- **พิสูจน์:** `ONLY=phase25 npm run test:clean` (PH25-06) · ลองลบ `carried_forward: false` ใน `findPassedSubjectIds` แล้วรันใหม่ → เทส B1 fail (คืนโค้ดหลังลอง)
