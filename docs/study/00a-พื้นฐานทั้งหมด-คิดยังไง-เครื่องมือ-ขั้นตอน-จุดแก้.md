## 1. ภาพใหญ่ในประโยคเดียว

> **ระบบเว็บ = ร้านอาหาร**

| ในร้านอาหาร | ในโปรเจกต์นี้ | อยู่ที่ไหน |
|---|---|---|
| ลูกค้า | ผู้ใช้ที่เปิดเว็บใน browser | — |
| เมนู + หน้าร้าน (สิ่งที่ลูกค้าเห็น) | **Frontend** (React) — หน้าจอ ปุ่ม ฟอร์ม | `frontend/src/design/*.jsx` |
| พนักงานรับออเดอร์ | **Backend** (Express) — รับคำขอ ตรวจสิทธิ์ ตรวจกฎ | `backend/src/modules/*` |
| คนไปหยิบของในโกดัง | **Prisma** — แปลง JavaScript เป็นคำสั่ง SQL | `backend/src/modules/*/*.repository.js` |
| โกดัง | **ฐานข้อมูล** (PostgreSQL) — เก็บข้อมูลจริง | ตารางตาม `backend/prisma/schema.prisma` |
| ใบออเดอร์ที่ส่งไปมา | **API** (HTTP request/response แบบ JSON) | เช่น `POST /api/subjects` |

**กฎข้อเดียวที่ต้องจำ:** ลูกค้าไม่เดินเข้าโกดังเอง — หน้าเว็บ **ห้าม** คุยกับฐานข้อมูลตรง ต้องผ่าน backend เสมอ
เพราะ backend คือที่ตรวจว่า "คนนี้มีสิทธิ์ไหม" และ "ข้อมูลที่ส่งมาถูกกฎไหม"
(หน้าเว็บตรวจเองก็ได้ แต่แค่เพื่อความสะดวกของผู้ใช้ — คนยิง API ตรงๆ ข้ามหน้าเว็บได้ จึงเชื่อได้แต่ backend)

## 2. "คิดอันนี้มาได้ไง" — ลำดับความคิดก่อนเขียนโค้ดบรรทัดแรก

นักพัฒนาไม่ได้นั่งเขียนโค้ดไปเรื่อยๆ แต่คิดเป็น 5 คำถาม เรียงตามนี้เสมอ:

```
1. ใครใช้? ทำอะไรได้?        → ผู้ใช้ 3 กลุ่ม + สิทธิ์   (CLAUDE.md / รายงาน)
2. ต้องจำข้อมูลอะไร?          → ออกแบบตาราง              (schema.prisma)
3. ต้องมีคำสั่งอะไรให้เรียก?   → ออกแบบ API               (routes.js)
4. กฎอะไรที่ห้ามพัง?          → กฎธุรกิจ                 (controller.js)
5. ผู้ใช้เห็นและกดอะไร?       → หน้าจอ                   (*.jsx)
```

**ทำไมเริ่มจากข้อมูล (ข้อ 2) ก่อนหน้าจอ:** หน้าจอเปลี่ยนง่าย ตารางเปลี่ยนยาก (มีข้อมูลจริงอยู่แล้ว)
ถ้าตารางผิดตั้งแต่ต้น ทุกชั้นข้างบนต้องแก้ตาม

**ตัวอย่างจริง — ฟีเจอร์ "จัดการรายวิชา" คิดมาแบบนี้:**

| คำถาม | คำตอบของฟีเจอร์นี้ | ผลลัพธ์ในโค้ด |
|---|---|---|
| 1 ใครใช้ | เจ้าหน้าที่เพิ่ม/แก้/ลบ · ทุกคนดูรายการได้ | `requireRole("officer")` ที่ POST/PUT/DELETE |
| 2 จำอะไร | รหัสวิชา + ชื่อวิชา | `model Subject` (`subject_code`, `subject_name`) |
| 3 คำสั่งอะไร | ดู / เพิ่ม / แก้ / ลบ | 4 เส้นใน `subjects.routes.js` |
| 4 กฎอะไร | ห้ามรหัสซ้ำ · ห้ามว่าง · ห้ามลบวิชาที่มีรอบ/ผลสอบใช้อยู่ | `subjects.controller.js` |
| 5 หน้าจออะไร | ตาราง + ปุ่มแก้/ลบ + ฟอร์มเด้ง (modal) | `manageRoundsSubjectsReal.jsx` |

> ทุกฟีเจอร์ในระบบนี้ใช้ 5 คำถามเดิม เปลี่ยนแค่คำตอบ

## 3. เครื่องมือ — แต่ละอันมีไว้ทำอะไร

| เครื่องมือ | ทำอะไร | คำสั่ง/วิธีใช้ที่ใช้จริงในโปรเจกต์ |
|---|---|---|
| **VS Code** | เขียน/อ่านโค้ด | `Ctrl+P` เปิดไฟล์ตามชื่อ · `Ctrl+Shift+F` ค้นทั้งโปรเจกต์ · `Ctrl+F` ค้นในไฟล์ · `F12` บน function = ไปดูต้นทาง |
| **Node.js** | รันโค้ด JavaScript นอก browser (backend ทำงานบนนี้) | `node ไฟล์.js` |
| **npm** | ติดตั้งแพ็กเกจ + รันสคริปต์ที่ตั้งไว้ใน `package.json` | `npm install` · `npm start` (backend) · `npm run dev` (frontend) |
| **Express** | ไลบรารีทำ backend: รับ request → เรียกฟังก์ชัน → ตอบ response | อยู่ใน `app.js` |
| **PostgreSQL** | ฐานข้อมูลตัวจริง เก็บข้อมูลเป็นตาราง | รันเป็น service ในเครื่อง |
| **Prisma** | ตัวกลางให้ JS คุยกับ PostgreSQL ไม่ต้องเขียน SQL เอง | `schema.prisma` = แบบแปลนตาราง · `npx prisma migrate dev` = สร้าง/แก้ตารางจริง · `npx prisma studio` = เปิดดูตารางเป็นหน้าเว็บ |
| **React + Vite** | สร้างหน้าจอ · Vite = ตัวรันเว็บตอนพัฒนา อัปเดตทันทีที่เซฟ | `npm run dev` ที่โฟลเดอร์ `frontend` |
| **Git** | เก็บประวัติการแก้ไข ย้อนกลับได้ | `git status` · `git diff` · `git add <ไฟล์>` (ทีละไฟล์ ห้าม `git add .`) · `git commit` · `git checkout -- <ไฟล์>` = ทิ้งสิ่งที่แก้ |
| **Browser DevTools** (กด `F12`) | ดูว่าหน้าเว็บส่งอะไรไป backend ได้อะไรกลับมา | แท็บ **Network** = ดูทุก request · แท็บ **Console** = ดู error |
| **REST Client / curl** | ยิง API เองโดยไม่ผ่านหน้าเว็บ — พิสูจน์ว่า backend ถูกก่อนไปโทษหน้าจอ | `backend/requests.http` (กด Send Request) |
| **ไฟล์เทส** | ให้คอมพิวเตอร์ตรวจแทนเราว่ากฎยังไม่พัง | `npm run test:clean` (ใช้ฐานชั่วคราว ไม่แตะข้อมูลจริง) |

**เปิดโปรเจกต์ขึ้นมาทำงาน = เปิด 2 terminal:**
```bash

cd backend
npm start          # แก้โค้ด backend แล้วต้อง Ctrl+C แล้ว npm start ใหม่ ทุกครั้ง

# terminal 2 — frontend (พอร์ต 5174)
cd frontend
npm run dev        # แก้โค้ด frontend แล้ว browser อัปเดตเอง
```

## 4. เส้นทางของ 1 คำสั่ง — ตามรอยตอนกด "บันทึก" ในฟอร์มเพิ่มวิชา

นี่คือหัวใจ ถ้าเข้าใจเส้นทางนี้เส้นเดียว ทุกฟีเจอร์ในระบบก็เป็นแบบเดียวกัน

```
[ผู้ใช้กดปุ่ม "บันทึก"]
        │
        ▼  ① FRONTEND   manageRoundsSubjectsReal.jsx
        │     SubjectModal เก็บ code, name ใน state → กดบันทึก → onSave({subject_code, subject_name})
        │     saveSubject() เรียก  apiFetch('/subjects', { method:'POST', body: form })
        │
        ▼  ② ส่งผ่านเครือข่าย  (เห็นได้ใน DevTools → Network)
        │     POST http://localhost:3000/api/subjects     + cookie ที่มี JWT   + body JSON
        │
        ▼  ③ BACKEND app.js
        │     app.use("/api/subjects", subjectsRouter)  → ส่งต่อไปที่ subjects.routes.js
        │
        ▼  ④ ROUTES   subjects.routes.js
        │     router.post("/", authenticate, requireRole("officer"), createAll)
        │                      │              │                      └─ ฟังก์ชันที่จะทำงานจริง
        │                      │              └─ ด่าน 2: role ต้องเป็น officer ไม่งั้น 403
        │                      └─ ด่าน 1: ต้อง login (มี token ถูกต้อง) ไม่งั้น 401
        │
        ▼  ⑤ CONTROLLER   subjects.controller.js → createAll
        │     cleanSubjectInput()  ตรวจว่าไม่ว่าง ไม่ยาวเกิน        → ผิด = 400
        │     ensureCodeFree()     ตรวจว่ารหัสไม่ซ้ำ                 → ซ้ำ = 409
        │
        ▼  ⑥ REPOSITORY   subjects.repository.js → create(data)
        │     prisma.subject.create({ data })   ← Prisma แปลงเป็น INSERT INTO subjects ...
        │
        ▼  ⑦ DATABASE   ตาราง subjects เพิ่ม 1 แถว
        │
        ▼  ⑧ ตอบกลับย้อนทางเดิม   res.json({ success: true, data: subject })
        │
        ▼  ⑨ FRONTEND  toast "บันทึกแล้ว" → ปิด modal → loadSubs() ดึงรายการใหม่มาแสดง
```

**แต่ละชั้นรับผิดชอบอะไร (ห้ามปนกัน):**

| ชั้น | ไฟล์ | หน้าที่ | ห้ามทำ |
|---|---|---|---|
| routes | `*.routes.js` | บอกว่า URL ไหน + วิธีไหน → ใคร (ฟังก์ชัน) ทำ · ใครมีสิทธิ์ | ห้ามมีกฎธุรกิจ |
| controller | `*.controller.js` | ตรวจข้อมูล · ตรวจกฎ · สั่ง repository · ตอบกลับ | ห้ามเรียก Prisma ตรงๆ |
| repository | `*.repository.js` | คุยกับ Prisma/ฐานข้อมูลอย่างเดียว | ห้ามตรวจกฎ ห้ามรู้จัก `req`/`res` |

เหตุผลที่แยก: ตอนแก้ ถ้ารู้ว่าเรื่องไหนอยู่ชั้นไหน จะรู้ทันทีว่าเปิดไฟล์ไหน
(กฎ → controller · คำสั่งฐานข้อมูล → repository · สิทธิ์/URL → routes)

**รูปแบบคำตอบที่ตกลงกันระหว่างหน้าเว็บกับ backend (contract):**
```js
สำเร็จ:  { success: true, data: ... }
ผิดพลาด: { success: false, message: "ข้อความภาษาไทยที่ผู้ใช้อ่านได้" }   + status code (400/401/403/404/409)
```
ฝั่ง controller โยน error ด้วย `throw httpError("ข้อความ", 409)` แล้ว `next(err)` ส่งให้ `errorHandler` แปลงเป็นรูปแบบข้างบน

**Status code ที่ต้องรู้ (ใช้ซ้ำทั้งระบบ):**

| code | ความหมาย | ตัวอย่างในระบบ |
|---|---|---|
| 200 | สำเร็จ | |
| 400 | ข้อมูลที่ส่งมาไม่ถูก | รหัสวิชาว่าง |
| 401 | ยังไม่ login / token หมดอายุ | |
| 403 | login แล้วแต่ไม่มีสิทธิ์ | นักศึกษาพยายามลบวิชา |
| 404 | ไม่พบสิ่งที่ขอ | |
| 409 | ขัดแย้งกับข้อมูลที่มีอยู่ | รหัสวิชาซ้ำ · ลบวิชาที่มีคนใช้ |
| 500 | โค้ดเราพัง (บั๊ก) | |

□ 1. เขียนเป็นประโยคก่อน        "เจ้าหน้าที่ต้องใส่หน่วยกิตให้วิชาได้ (0–20)"

## 6. ตัวอย่างลงมือจริง — "เพิ่มช่องหน่วยกิต (credits) ให้วิชา" ต้องแก้ตรงไหนบ้าง

โจทย์: เจ้าหน้าที่ใส่หน่วยกิต (เลข 0–20) ตอนเพิ่ม/แก้วิชาได้ และเห็นในตาราง

> ⚠️ ฝึกแบบนี้บนฐานข้อมูลชั่วคราวหรือถามมังกรก่อน — อย่า `migrate` ใส่ฐานข้อมูลเดโมโดยไม่ตั้งใจ

### ขั้น 2 — ตาราง · `backend/prisma/schema.prisma`
```prisma
model Subject {
  subject_id   Int             @id @default(autoincrement())
  subject_code String          @db.VarChar(10)
  subject_name String          @db.VarChar(200)
  credits      Int?                                  // ← เพิ่มบรรทัดนี้
  results      SubjectResult[]
  @@map("subjects")
}
```
- `Int?` = เป็นเลขหรือเว้นว่างได้ — **ต้องใส่ `?`** เพราะวิชาที่มีอยู่แล้วยังไม่มีค่านี้ ถ้าไม่ใส่ `?` migration จะพัง
- จากนั้นสั่งให้ Prisma สร้างคอลัมน์จริงในฐานข้อมูล:
```bash
cd backend
npx prisma migrate dev --name add_subject_credits
```
  จะได้ไฟล์ใหม่ใน `prisma/migrations/` (ต้อง commit ไปด้วย เพราะเครื่องอื่นใช้ไฟล์นี้สร้างตารางตาม)

### ขั้น 3 — routes · ไม่ต้องแก้
ยังเป็น 4 เส้นเดิม (ดู/เพิ่ม/แก้/ลบ) แค่ข้อมูลที่ส่งเข้าออกมีช่องเพิ่ม → **ไม่ต้องมี URL ใหม่**

### ขั้น 4 — controller (กฎ) · `subjects.controller.js` → `cleanSubjectInput`
ฟังก์ชันนี้ตรวจเฉพาะช่อง "ข้อความ" 2 ช่องใน loop `credits` เป็น "ตัวเลข" จึงต้องเพิ่มเอง
วางต่อจาก loop และ **ก่อนบรรทัด** `if (Object.keys(data).length === 0)`:
```js
  if (body?.credits !== undefined) {
    const credits = Number(body.credits);
    if (!Number.isInteger(credits) || credits < 0 || credits > 20) {
      throw httpError("หน่วยกิตต้องเป็นจำนวนเต็ม 0–20", 400);
    }
    data.credits = credits;
  }
```
- ทำไมต้องกรองเองทีละช่อง: ฟังก์ชันนี้ตั้งใจ **ไม่ส่ง `req.body` ทั้งก้อนลงฐานข้อมูล** (กันคนแอบส่งช่องแปลกๆ มาแก้) ช่องไหนไม่ได้ลิสต์ไว้จะถูกทิ้ง
  → ถ้าลืมขั้นนี้ ส่ง `credits` ไปแล้ว backend จะเงียบๆ ไม่บันทึก (อาการนี้พบบ่อย!)

### ขั้น 5 — repository · ไม่ต้องแก้
- `create(data)` / `updata(id, data)` ส่ง `data` ต่อให้ Prisma ตรงๆ อยู่แล้ว
- `findAll()` ใช้ `findMany` ซึ่งดึง **ทุกคอลัมน์** อัตโนมัติ → `credits` จะมากับ response เอง

### ขั้น 6 — พิสูจน์ backend ก่อน (ยังไม่แตะหน้าจอ)
1. `Ctrl+C` ที่ terminal backend แล้ว `npm start` ใหม่ (ไม่มี auto-reload)
2. เปิด `backend/requests.http` ยิง login แล้วยิง `POST /api/subjects` ใส่ `"credits": 3`
3. ลองส่งผิดดูด้วย: `"credits": 99` ต้องได้ 400 พร้อมข้อความ — **เทสด้านที่ควรพังเสมอ**
4. `npx prisma studio` เปิดตาราง `subjects` ดูว่าแถวมีเลข 3

### ขั้น 7 — frontend · 3 จุดใน `manageRoundsSubjectsReal.jsx` + 1 จุดใน `i18n.js`
| จุด | ที่ไหน | แก้อะไร |
|---|---|---|
| ฟอร์ม | `function SubjectModal` | เพิ่ม `const [credits, setCredits] = useState('')` · ใน `useEffect` ใส่ `setCredits(subject?.credits ?? ## 7. "ถ้าจะแก้เรื่องนี้ ต้องไปไหน" — ตารางตัดสินใจ

ไม่ต้องจำไฟล์ จำแค่ **ประเภทของงาน** แล้วรู้ชั้นที่ต้องไป

| งานที่ต้องการ | ชั้นที่แก้ | ไฟล์ตัวอย่าง |
|---|---|---|
| เปลี่ยนตัวเลขกฎ (เช่น แนบไฟล์ได้กี่ไฟล์) | controller (+ frontend ถ้ามีค่าซ้ำฝั่งหน้าจอ) | `certificates.controller.js` → `MAX_FILES_PER_RESULT` และ `evidenceFiles.js` |
| เปลี่ยนข้อความ error | controller (ข้อความใน `httpError(...)`) | `*.controller.js` |
| เปลี่ยนคำบนหน้าจอ | `i18n.js` (ไทย + อังกฤษ ทั้ง 2 ชุด) | `frontend/src/design/i18n.js` |
| ใครทำอะไรได้ | routes → `requireRole(...)` และเมนูฝั่งหน้าจอ | `*.routes.js` + `app.jsx` → `ROLE_PAGES`, `NAV` |
| เพิ่มช่องข้อมูล | schema → migrate → controller(ตรวจ) → frontend(ฟอร์ม/ตาราง) | ตัวอย่างข้อ 6 |
| เพิ่ม API เส้นใหม่ | routes → controller → repository → ลงทะเบียนใน `app.js` ถ้าเป็นโมดูลใหม่ | `app.js` มี `app.use("/api/...")` |
| เพิ่มหน้าจอ/เมนูใหม่ | สร้าง `*.jsx` → เพิ่มใน `NAV` และ `ROLE_PAGES` ของ `app.jsx` → ข้อความใน `i18n.js` | `app.jsx` |
| เปลี่ยนสี/ขนาด | CSS | `styles.css` (ตัวแปร `:root`) |
| เปลี่ยนวิธีคิดสถิติ/ผ่านไม่ผ่าน | backend เท่านั้น (frontend ห้ามคำนวณเอง) | `dashboard.service.js` |
| เปลี่ยนรูปแบบไฟล์ Excel/PDF | backend | `dashboard.controller.js`, `utils/xlsxExport.js` |

**กฎตัดสินว่าอยู่ฝั่งไหน:**
- "ถ้าข้ามหน้าเว็บแล้วยิง API ตรงๆ จะต้องยังถูกบังคับไหม?" → **ใช่ = backend** (ความปลอดภัย, กฎธุรกิจ, สิทธิ์, การคำนวณ)
- "แค่ทำให้ผู้ใช้สะดวก/สวย" → frontend (ข้อความ, สี, การจัดวาง, แจ้งก่อนว่าผิด)
- ถ้าไม่แน่ใจ ทำทั้งสองฝั่ง แต่ **backend คือตัวจริง**

**ไม่รู้ว่าโค้ดอยู่ไหน — วิธีหา (ใช้ได้ทุกกรณี):**
1. เปิดหน้าเว็บ กด `F12` → Network → กดปุ่มที่สนใจ → ดูชื่อ URL ที่ถูกยิง (เช่น `/api/subjects`)
2. `Ctrl+Shift+F` ค้น `/subjects` ใน `frontend` → เจอไฟล์หน้าจอที่ยิง
3. `Ctrl+Shift+F` ค้น `api/subjects` ใน `app.js` → เจอ routes → เปิดตามเส้นทางในข้อ 4
4. หรือค้น "ข้อความที่เห็นบนจอ" ใน `i18n.js` → ได้ key → ค้น key นั้นในโค้ด → เจอหน้าจอ

## 8. เมื่อมันพัง — ไล่หาสาเหตุเป็นขั้น (อย่าเดา)

```
อาการ: กดแล้วไม่เกิดอะไร / ขึ้น error
  │
  ├─ 1. F12 → Console   มีข้อความแดงไหม?          → โค้ดหน้าจอพัง (อ่านบรรทัดที่บอก)
  ├─ 2. F12 → Network   request ถูกยิงไหม? status อะไร?
  │       ├─ ไม่ถูกยิงเลย              → ปัญหาที่ onClick / ฟังก์ชันในหน้าจอ
  │       ├─ 401 / 403                 → login/สิทธิ์ (routes: authenticate, requireRole)
  │       ├─ 400 / 409                 → กฎใน controller ปฏิเสธ → อ่าน message ใน Response
  │       ├─ 404                       → URL ผิด หรือ id ไม่มี
  │       └─ 500                       → ดู terminal ของ backend (มี error เต็ม + บรรทัด)
  ├─ 3. ยิง API เองด้วย requests.http   ผ่าน = backend ถูก ปัญหาอยู่หน้าจอ · ไม่ผ่าน = ปัญหาอยู่ backend
  └─ 4. npx prisma studio   ข้อมูลในตารางเป็นอย่างที่คิดไหม?
```

อาการที่พบบ่อยของมือใหม่:
| อาการ | สาเหตุที่เจอบ่อย |
|---|---|
| แก้ backend แล้วไม่เปลี่ยน | ลืม restart `npm start` |
| ส่งช่องใหม่ไปแล้วไม่ถูกบันทึก | controller กรองช่องทิ้ง (ยังไม่ได้ลิสต์ช่องใหม่) |
| เพิ่มคอลัมน์แล้ว backend error | ลืมรัน `prisma migrate dev` / ลืม `?` ทำให้ผิดกับแถวเก่า |
| หน้าจอขึ้น key แปลกๆ เช่น `roundsMgmt.colCredits` | ลืมเพิ่ม key ใน `i18n.js` (หรือเพิ่มแค่ชุดเดียว) |
| 401 ทุกอย่างหลังแก้ | cookie หมดอายุ → login ใหม่ |
